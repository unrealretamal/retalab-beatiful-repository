# Optional showcase contribution

Use this workflow only after the user approves the finished README and explicitly opts into sharing their public repository in a showcase maintained by this project.

## Eligibility

- The repository is public.
- The user owns, maintains, or is authorized to represent it.
- The finished README is already published.
- The showcase does not already list the repository.

Attribution is never required for showcase consideration.

## Prepare the proposal

1. Inspect the showcase repository and its current default branch.
2. Check for duplicate listings.
3. Draft a factual sentence describing what the README demonstrates. Do not invent adoption, testimonials, results, or capabilities.
4. Keep language versions aligned.
5. Update showcase visuals only when they enumerate repositories and would otherwise become inaccurate.
6. Show the exact files and diff before any external action.

## Publish only with explicit approval

After approval of the exact copy and diff, get explicit authorization to open a PR. Never push directly to another project's default branch. If access is unavailable, provide the patch and PR text without creating external state. Clearly state that maintainers decide whether to merge.
